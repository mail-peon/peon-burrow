# ADR-0004 · 默认端口 41316，且绝不静默换端口

- **状态**：已采纳
- **影响面**：`peon-burrow`（产品层的 `config` 模块）、端口占用处理、发现文件、与 `mail-peon` 扩展的联动
- **完整设计**：[`design/port-and-discovery.md`](../design/port-and-discovery.md)

---

## 背景

现状是固定 **8787**（`--port` / `PORT` 可改）。用户提出两点：

1. 「7878 感觉会有冲突（我不确定）」；
2. 「希望端口能配置，或者找个不常用的固定端口」。

「8787 会不会撞车」这个怀疑**是对的**。查 IANA
[service-names-port-numbers](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.csv)：

| 端口 | IANA 登记 |
| --- | --- |
| 7878 | `owms` / Opswise Message Service（tcp），udp 为 Reserved |
| 8787 | `msgsrvr` / Message Server（tcp + udp） |

两个都已经**被分配**，而且都是「消息服务」类软件 —— 撞上之后行为冲突会很诡异。

## 问题

| # | 问题 |
| --- | --- |
| Q1 | 端口能不能「让系统自己分配」（`:0` + 发现文件）？ |
| Q2 | 默认端口选哪个？ |
| Q3 | 被占用时怎么办？ |

## 决策

### 1. Q1：不行 —— **扩展读不了本机文件**

| 端 | 能读发现文件吗 |
| --- | --- |
| 中继 / CLI / 安装器 GUI | ✅ |
| **浏览器扩展** | ❌ 只能靠「用户填的地址」或**内置默认值** |

扩展侧 `mail-peon/src/adapters/mail/providers/imap/index.ts:62` 就是一个写死的默认值。
所以**默认端口必须固定且稳定**；发现文件是做给**人、CLI、GUI** 用的。

**推论（本条最关键）：绝不静默回退到别的端口。** 那会造成最糟的失败模式 ——
服务在跑、扩展永远连不上，而两边都不说「端口不对」。

### 2. Q2：默认 **41316**

四条硬约束同时满足后，在 40000–49151 里挑一个有助记的：

| 约束 | 41316 |
| --- | --- |
| 不在 IANA 注册表（tcp/udp 都无） | ✅（2026-10-09 核验） |
| < 49152（Windows 动态端口起始） | ✅ |
| 不在 Windows 排除区间（Hyper-V/WSL 批量保留） | ✅（本机排除区间全在 5xxxx） |
| 避开常见开发端口 | ✅ |

**为什么是 41316**：`4` + `M`(13) + `P`(16) = mail-**P**eon。可助记，用户手改配置 / 看日志时有据可查。

优先级：CLI > 环境变量（沿用 `PORT`）> `relay.toml` > 默认 `41316`。用户可以随便改，
只是**改完要同时改扩展里的地址** —— 这条必须出现在提示文案里。

### 3. Q3：三种情况三种处理，**不做破坏性动作**

| 情形 | 行为 |
| --- | --- |
| 占用者是**我们自己的旧实例** | 视为「已在运行」：退出码 0，刷新发现文件。（服务化后「启动一个已在运行的服务」是常态） |
| 占用者是**别的进程** | **失败**：退出码 3，日志 + 状态文件写明 PID/进程名 + 三条出路。**不换端口、不杀进程** |
| 前台 `run --force-port` | 唯一例外：结束占用者再绑定。**仅前台**，服务态忽略该参数 |

这是对 TS 版 `[Y/n]` 交互 + `taskkill` 的**有意偏离**：

- 服务态没有 TTY，交互提问等于挂死；
- 后台服务不该有「杀任意进程」的能力（TS 版能这么做，是因为它永远跑在用户终端里）。

## 后果

### 好的

- 端口有据可查（IANA + 动态区间 + 排除区间三条核验，写进发版 checklist）；
- 冲突时用户拿到的是「谁占着 + 怎么办」，而不是一串 `EADDRINUSE`；
- 「已在运行」被正确识别，服务化带来的重复启动不再报错。

### 代价（如实记录）

| 代价 | 说明 |
| --- | --- |
| **与扩展的默认值不一致，直到 P6 联动完成** | 过渡期用户必须手填 `ws://127.0.0.1:41316/`；安装器界面要**一键复制**这个地址 |
| 端口号变化会打断既有用户 | 8787 仍可手动配置（`port = 8787`），但默认值变了。README / 安装器要写明这次迁移 |
| `41316` 需要定期复核 | 几年后 OS 可能改动态端口范围；发版 checklist 里有一条「复核 IANA + 排除区间」 |

### 否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 保持 8787 | IANA 已分配；且撞上的还是「Message Server」这类软件 |
| 7878 | IANA 已分配（用户直觉正确） |
| `:0` + 发现文件 | 扩展读不了文件（决策 1） |
| 在 41316 附近**自动试探**可用端口 | 扩展只认固定默认值，换端口 = 静默失联 |
| 保留 TS 版的交互式 `[Y/n]` 杀进程 | 服务态无 TTY；且后台服务不该有杀进程能力 |
