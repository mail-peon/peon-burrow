# 设计 · 端口与发现

> 结论先说：**默认端口 `41316`；可配置；被占用时绝不静默换端口。**

---

## 1. 为什么不能靠「自动挑一个空闲端口」

用户（和最初的直觉方案）常提「监听 `127.0.0.1:0` 让系统分配 + 写发现文件」。
这条方案在这里**行不通**，原因是链路两端的能力不对等：

| 端 | 能读发现文件吗 | 结论 |
| --- | --- | --- |
| 中继（本机进程） | ✅ 能写、能读 | —— |
| 安装器 GUI / CLI / `doctor` | ✅ 能读 | —— |
| **浏览器扩展** | ❌ **读不了本机文件** | 扩展只能靠**用户填的地址**或**内置默认值**连中继 |

扩展侧 `providers/imap/index.ts:62` 给的是一个**写死的默认值**，
用户可以改，但绝大多数用户不会改。所以：

> **默认端口必须是固定且稳定的**，否则「装完就能用」这条主线断掉。
> 发现文件是做给**人、CLI、GUI** 用的，不是给扩展用的。

**推论：绝不能静默回退到别的端口。** 那会造成最糟的失败模式 ——
服务明明在跑，扩展却永远连不上，而两边都不报「端口不对」。

## 2. 为什么不用 8787（现状）和 7878（最初的候选）

用户的怀疑是对的。查 IANA
[service-names-port-numbers](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.csv)：

| 端口 | IANA 登记 | 备注 |
| --- | --- | --- |
| **7878** | `owms` / **Opswise Message Service**（tcp），udp Reserved | **已被分配** |
| **8787** | `msgsrvr` / **Message Server**（tcp + udp） | **已被分配**；且 TS 版现状就在用它 |

两者都在 IANA 的注册端口段（1024–49151），撞上真实软件的几率不低
——更糟的是撞上的还都是「消息服务」类的软件，行为冲突会很诡异。

## 3. 选默认端口的四条硬约束

| # | 约束 | 理由 | 核验方式 |
| --- | --- | --- | --- |
| C1 | **不在 IANA 注册表里**（tcp 与 udp 都不能有行） | 不与任何登记服务抢 | 下载 IANA CSV，`grep '^[^,]*,41316,'` 应无输出 |
| C2 | **< 49152**（Windows 动态端口起始） | 落在动态区间里可能被系统**临时分配给一条出站连接**，导致监听偶发失败 | `netsh int ipv4 show dynamicport tcp` |
| C3 | **不在 Windows 排除区间** | Hyper-V / WSL / Docker 会批量保留端口段（本机实测：`50633-50732`、`53357-53456`、`54682-54781`、`57746-57845`、`58024-58123`、`58224-58323`），撞上就永远绑不上，且报错毫无线索 | `netsh int ipv4 show excludedportrange protocol=tcp` |
| C4 | **避开常见开发端口** | 3000/5173/8000/8080/8081/8888/9000/9090/6379/5432/1433/1080/3128… 用户机器上跑着一堆开发服务是常态 | 人工集合，写进 `doctor` 的提示 |

四条同时满足后，在 **40000–49151** 里挑一个**有助记**的号。

### 3.1 候选核验（2026-10 实测）

| 候选 | IANA（tcp/udp） | ≥ 49152? | 本机排除区间? | 结论 |
| --- | --- | --- | --- | --- |
| **41316** | 未分配 | 否 | 否 | ✅ **选它** |
| 41337 / 41253 / 43717 / 45789 / 47381 / 47653 | 未分配 | 否 | 否 | 备选（`port_fallbacks` 里不做自动回退，仅供用户手改时参考） |

**为什么是 41316**：`4` + `M`(13) + `P`(16) = mail-**P**eon → `4-13-16`。
有助记的端口在**用户手改配置 / 看日志 / 写工单**时省事，也让「为什么是这个号」有据可查。

> ⚠️ 号本身不重要，**核验过程**重要。发版前把上面三条命令跑一遍，
> 结果写进 `ai-docs/decisions/` 里一份带日期的附录（防止几年后 OS 改了动态端口范围）。

## 4. 配置

优先级（高 → 低）：

```
CLI 参数  >  环境变量  >  配置文件  >  内置默认值
```

| 来源 | 写法 | 谁用 |
| --- | --- | --- |
| CLI | `burrow run --port 41317` | 调试 / 脚本 |
| ENV | `PORT=41317`（**沿用 TS 版变量名**） | 服务宿主注入、CI |
| 配置文件 | `relay.toml` 的 `port = 41317` | **服务形态的唯一正路** |
| 默认 | `127.0.0.1:41316` | 零配置 |

`relay.toml`（位置见 [`01-architecture.md § 6`](../01-architecture.md)）：

```toml
# 监听地址。默认只绑本机 —— 中继能看到邮箱明文凭据。
host = "127.0.0.1"
port = 41316

# 可选：要求 ?token=… 匹配（放到非 loopback 时**必须**设）
# token = ""
# 可选：允许的邮件服务器（支持 * 通配）。空 = 不限制
# allowed_hosts = ["imap.qq.com", "*.gmail.com", "*.outlook.com"]
# 是否校验证书链。**不要**为了省事关掉
tls_reject_unauthorized = true
# 单条连接空闲超时（秒）
idle_timeout_secs = 900
# 并发连接上限（每账号 watch 占 1 条）
max_connections = 32
# 是否允许把原始字节打进日志（含明文凭据！）
# trace = false
# 自更新
[update]
channel = "stable"          # stable | beta
check_interval_hours = 24
# base_url = "https://gh-proxy.example.com/https://github.com"   # 镜像站
```

GUI 的「端口」只读显示 + 「打开配置文件」按钮；**不在 GUI 里改端口**：
改端口必须重启服务，而重启会让所有 watch 连接重连 —— 这属于「高级操作」，
放配置文件里更不容易被误触。

## 5. 端口被占用时的行为

**三种情况，三种处理**（服务态与前台模式行为一致，只有 `--force-port` 例外）：

### 5.1 占用者是我们自己的旧实例 → 视为「已在运行」

判定方式：**连控制面**（[`control-plane-ipc.md`](./control-plane-ipc.md)）并问 `Status`：

- 收到合法响应 → 说明中继已经在跑。行为：**退出码 0**，日志写
  「已在运行（PID x，端口 41316），无需重复启动」，并把发现文件刷新成对方的真实信息。
- 这一步很重要：服务化以后，**「启动」被调用而它已经在跑**是常态
  （用户点两次、系统 watchdog 拉一次、自更新后重启一次），不能当成错误。

### 5.2 占用者是别的进程 → 明确失败，不做任何破坏性动作

| 动作 | 内容 |
| --- | --- |
| 退出码 | `3`（端口被占用） |
| 日志 | `端口 41316 已被 PID 8899（chrome.exe）占用` + 一句「怎么办」 |
| 状态文件 | `lastError = "port-in-use"`，GUI 状态页直接显示这一段 |
| **不**做的事 | ❌ 不静默换端口 ❌ 不杀进程 ❌ 不重试到天荒地老 |

「怎么办」的文案要给三条可执行的出路：

```
1) 找出占用者： burrow doctor --port
2) 换一个端口： 改配置 relay.toml 的 port，然后重启服务
   （注意：扩展里也要填同样的地址 ws://127.0.0.1:<新端口>/）
3) 前台临时跑： burrow run --port 41317
```

### 5.3 前台模式的例外：`--force-port`

调试时「端口被上次没退干净的进程占着」确实烦（TS 版为此做了 `[Y/n]` 交互，`imap-relay.ts:1686-1741`）。
Rust 版把它降级成**显式参数**：

```bash
burrow run --force-port        # 找到占用者 → 打印是谁 → 结束它 → 重新绑定
```

约束：

- **只在 `run`（前台）下有效**；服务态忽略该参数并记一条警告 ——
  一个后台服务**不该**有「杀掉任意进程」的能力（TS 版能这么做是因为它永远跑在用户终端里）；
- 只杀**具体 PID**，绝不按进程名匹配（TS 版同样如此，`imap-relay.ts:1599-1610`）；
- 杀完等 300 ms 再 bind（内核回收监听套接字有延迟，`imap-relay.ts:1725`）；
- 非交互环境（无 TTY）下不提问、直接执行参数语义。

### 5.4 端口探测命令

`doctor --port` 输出（三平台统一格式）：

```
端口 41316
  状态      : 被占用
  占用者    : PID 8899  chrome.exe
  监听地址  : 127.0.0.1:41316
  是否本中继: 否
  IANA      : 未注册（核验于 2026-10-09）
  动态区间  : 49152-65535（未落入）
  排除区间  : 未落入
  建议      : 见日志中的三条出路
```

## 6. 发现文件

原子写（写临时文件 + rename），每次**成功监听后**与**收到重启指令前**各写一次。
服务异常退出时**不删除**（留作证物），但内容里的 `pid` 会指向一个不存在的进程 ——
读取方必须校验 `pid` 是否活着，并在 `status` 里标注「陈旧」。

| 文件 | Windows | macOS | Linux |
| --- | --- | --- | --- |
| `relay.json` | `%LOCALAPPDATA%\peon-burrow\relay.json` | `~/Library/Application Support/peon-burrow/relay.json` | `~/.local/state/peon-burrow/relay.json` |

```json
{
  "schema": 1,
  "pid": 12345,
  "version": "0.1.0",
  "host": "127.0.0.1",
  "port": 41316,
  "url": "ws://127.0.0.1:41316/",
  "startedAt": "2026-10-09T04:07:40Z",
  "mode": "service",
  "serviceName": "peon-burrow",
  "autostart": "user-logon",
  "control": { "kind": "named-pipe", "path": "\\\\.\\pipe\\peon-burrow-imba97" }
}
```

| 字段 | 谁读 | 用途 |
| --- | --- | --- |
| `url` | GUI、CLI、**用户** | 「扩展里该填什么」——界面上一键复制，解决 P6 联动之前的过渡期 |
| `port` / `host` | `doctor`、GUI | 状态展示、冲突诊断 |
| `pid` / `startedAt` | GUI | 「真的活着吗」交叉验证（控制面才是权威） |
| `mode` / `serviceName` / `autostart` | GUI | 安装状态、自启状态（服务管理器是权威） |
| `control` | GUI / CLI | 控制面通道参数（**不含 token**；token 另有 0600 权限的文件） |

> ⚠️ **发现文件不是权威来源**，只是缓存。权威依次是：
> ① 控制面（进程内真实状态）→ ② 服务管理器（是否注册、是否自启）→ ③ 发现文件。

## 7. 监听地址

| 值 | 行为 |
| --- | --- |
| `127.0.0.1`（默认） | 只本机 |
| `::1` / `[::1]` | IPv6 回环；`url()` 输出要补方括号（TS 版 `displayHost()` 已有此逻辑，`imap-relay.ts:1483-1485`） |
| `localhost` | 解析到哪个由系统决定（可能双栈），**不推荐** |
| `0.0.0.0` | **允许但强烈不建议**：启动日志持续警告 + 自动要求 `token` 与 `allowed_hosts` 非空，否则**拒绝启动** |

最后一条是对 TS 版的收紧（TS 版只打警告，`imap-relay.ts:1352-1357`）：
「非 loopback + 无 token + 无白名单」= 把能看到邮箱明文的中继敞开给局域网，
这个组合不该只靠一行日志劝阻。

## 8. 验收

| # | 断言 |
| --- | --- |
| 1 | 干净环境下 `run` 起在 `127.0.0.1:41316`，发现文件内容与之一致 |
| 2 | `41316` 已被别进程占用 → 退出码 `3`，日志含占用者 PID/进程名，**没有**换端口 |
| 3 | 已被**自己的旧实例**占用 → 退出码 `0`，日志写「已在运行」，发现文件被刷新 |
| 4 | `run --port 0` → 内核分配端口，发现文件写真实端口（测试专用，扩展不依赖） |
| 5 | `host = "0.0.0.0"` 且无 token/白名单 → **拒绝启动**，退出码 `2` |
| 6 | `doctor --port` 的输出在「本中继 / 别进程 / 空闲」三种情况下都正确 |
| 7 | 服务重启后（自更新触发）端口与发现文件保持一致 |
| 8 | 发版前用 IANA CSV + `netsh show excludedportrange` 复核 `41316` 仍然干净（写进发版 checklist） |
